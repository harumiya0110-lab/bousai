# DISASTER SCOPE 開発計画

## 現状調査

- 調査日: 2026-11-04
- 初回構築時（2026-11-04）のワークスペースには既存アプリ、依存関係、設定、テストがありませんでした。
- 初期対象は愛媛県宇和島市ですが、地域を特定した実データをまだ取得・検証できていません。初期画面で実データが存在するような表示を行いません。

## 全体設計

- React + TypeScript + Viteを基盤にし、3D表示はReact Three Fiber/Three.js、操作状態はZustandで管理します。
- 地域設定、データソース情報、デモデータをアプリコードから分離します。すべてのレイヤは出典・データ区分・利用可能状態を持たせます。
- 仮想データは独立して切り替えられ、実データを確認・変換できるまでは「DEMO DATA」「仮想」と明示します。
- ローカル座標表示は可視化用途に限定し、測量精度や実際の避難安全性を主張しません。
- 公式出典・利用条件・安全上の限界を利用者が確認できるようにします。

- npm run test: 10テスト成功（地形メッシュ、仮想データ分類、保存形式、主要画面とナビゲーション）。
- npm run lint: 成功。
- Chromiumで本番プレビューを開き、3D画面、建物クリック、仮想施設の設置・保存、JSONリンクの出力内容を確認しました。配置・移動・削除も開発プレビューで操作確認しました。

## GeoJSONデータワークスペース追加（feature/geospatial-data-studio）

- 地理データ管理画面を追加し、GeoJSONのローカル取込、構造・座標範囲検証、メタデータ入力、IndexedDB保存、一覧、削除、GeoJSONエクスポートを実装。
- WGS84/OGC:CRS84の経緯度データを対象とし、未対応座標系を自動で推測しない。
- 3Dシミュレーションへ登録済みGeoJSONレイヤを連携。GeoJSON表示中は仮想デモ地形を隠し、面・線・点を相対縮尺の平面として表示。
- 大規模データの描画負荷を抑えるため、3Dプレビューに地物・頂点の上限を設定。IndexedDB内の元データはそのまま保持。各レイヤの個別表示切替、各ファイル20MB・合計100MBの保存上限も追加。
- GeoJSON検証テストを追加。このブランチのブラウザー実行・npm test・本番ビルドはまだ検証していないため、マージ前にローカル環境で必ず実行する。
- 公的機関からの実データ自動取得、CRS変換、DEM地形ドレープ、実際の道路経路探索は未実装。利用者によるGeoJSONの手動取込を先行実装した段階。
